# 休息日是一等考勤状态；出差工时不剔除休息日

节假日感知上线时有两个方向性选择，都不是实现细节，改主意代价高：

**1. 「休」写入数据库（`off` 状态值），不做展示层映射。** 备选方案是数据库保持「未到」、在各消费点按日历临时映射成「休」。选择一等状态是因为消费点当时已有 6 个以上（人员大板、考勤明细、两种 CSV 导出、汇总统计、apikey 对外 API），两套真相必然漂移；且历史上 1700+ 行周末「未到」需要一次性回填，回填后外部 API 契约里「休」就是既有事实，再改回去的成本只会更高。代价：`off` 进入对外 API 枚举，外部消费者必须容忍未知状态值。

**2. 出差日的固定工时不剔除行程中的休息日。** 备选方案是休息日上的出差行按 0h 计（我在设计评审时的推荐）。用户明确选了「出差天数 = 自然日天数，每天固定工时（默认 8h，`attendance.tripWorkHours` 可调）」——出差不因周末打折。这条口径记录在 CONTEXT.md「出差工时口径」，导出规则 `exportWorkHours` 实现它。若未来要改，注意这是业务口径变更而非 bug 修复。

节假日数据源（holiday-cn 年度 JSON vendored 在 `data/holidays/`，每年 11 月公告后随发版更新，缺数据年份回退仅周末规则并在同步摘要警告）是可逆的实现选择，不属于本 ADR 的范围。
